# 📂 Лабораторная работа №3

## 📝 Тема: Интеграционное тестирование проектов и работа с тестовыми заглушками

## 🎯 Что реализовано

Проект доработан до сквозного приложения с модульной архитектурой. Модули
общаются только через объединяющий их класс-контроллер, у которого нет
ни одной «зашитой» зависимости: все зависимости передаются в конструктор,
поэтому в тестах заменяются заглушками.

| Требование | Модуль | Класс |
| --- | --- | --- |
| a. Класс вычислений и валидации | `src/calculator.py` | `TriangleCalculator` |
| b. Класс работы с базой данных | `src/repository.py` | `TriangleRepository` |
| c. Класс взаимодействия с пользователем | `src/user_interaction.py` | `UserInteractionInterface` (ABC), `ConsoleUserInteraction` |
| d. Класс сторонней зависимости | `src/third_party.py` | `ThirdPartyInterface` (ABC), `SimulatedEmailSender` |
| e. Класс-контроллер | `src/controller.py` | `Controller` |
| Доменная логика из ЛР1 | `src/triangle.py` | `TriangleResult` + чистые функции |
| Точка входа | `src/main.py` | `main`, `build_controller` |

### Запись в базе данных

Одна строка таблицы `triangle_results` содержит `длина1`, `длина2`,
`длина3`, `тип_треугольника` и `сообщение_об_ошибке`. Первичный ключ —
тройка длин сторон, поэтому повторный запрос с теми же сторонами не
пересчитывается, а читается из базы как из кэша. Запрос с нечисловым вводом
не кэшируется: для него в базе просто нет ключа.

### Сценарий работы контроллера

1. `Controller.run()` получает три строки через `UserInteractionInterface`.
2. Строки преобразуются в числа: если ключа в БД нет, результат считается
   классом вычислений и сохраняется в БД, иначе результат читается из БД.
3. Строка-результат передаётся через `ThirdPartyInterface` стороннему сервису.
4. Метод возвращает строку-результат и показывает её пользователю.

Если сторонний сервис отказался принимать данные, к результату добавляется
соответствующее уведомление — отказ не приводит к потере вычислений.

## 🧪 Тесты

**Всего 88 тестов, из них 36 интеграционных.** Запуск выполняется из корня
репозитория, потому что тесты импортируют пакет `Lab3_KursDS`:

```bash
python -m unittest discover -v
```

| Файл | Тестов | Тип |
| --- | --- | --- |
| `tests/test_calculator.py` | 16 | юнит |
| `tests/test_repository.py` | 13 | юнит |
| `tests/test_user_interaction.py` | 11 | юнит |
| `tests/test_third_party.py` | 12 | юнит |
| `tests/test_controller.py` | 30 | **интеграционные** |
| `tests/test_main.py` | 6 | **интеграционные** |

Юнит-тесты не повторяют проверки Лабораторной работы №2: ЛР2 проверяла чистые
функции определения типа треугольника, здесь же тестируется новое поведение —
объект `TriangleResult`, тексты ошибок, операции над базой данных, интерфейсы
с абстрактными классами и чтение ввода из консоли. Логика определения типа
треугольника покрывается транзитивно, через публичный метод `calculate`.

### Заглушки (test doubles)

Проверка изоляции модулей выполнена настоящими заглушками:

* **пользовательский ввод** — класс `StubUserInteraction` из `tests/doubles.py`
  (реализует интерфейс и выдаёт заготовленные ответы), а также
  `unittest.mock.patch("builtins.input")` для консольной реализации;
* **отправка данных стороннему сервису** — `unittest.mock.Mock(spec=ThirdPartyInterface)`,
  а также `patch.object(SimulatedEmailSender, "send")`: тест проверяет, что
  при подменённом методе лог-файл не создаётся вовсе;
* **база данных** — `:memory:` и временные папки `tempfile.TemporaryDirectory()`,
  поэтому тесты не зависят от рабочих данных;
* **вычисления** — `Mock(spec=TriangleCalculator)`, чтобы доказать, что при
  попадании в кэш метод `calculate` действительно не вызывается.

## 🚀 Запуск приложения

Запуск выполняется как модуль, из корня репозитория:

```bash
python -m Lab3_KursDS.src.main
```

Приложение запросит три длины сторон, создаст базу данных `data/triangles.db`,
выведет результат и запишет имитацию отправки письма в `Logs/email_log.txt`.
Сторонний сервис ничего не отправляет — используется только имитация.
